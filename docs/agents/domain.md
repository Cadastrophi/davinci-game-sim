# Domain documentation configuration

This is a single-context repository.

- Read `CONTEXT.md` before planning or implementation.
- Put stable domain vocabulary and boundaries in `CONTEXT.md`.
- Put product direction, goals, non-goals, and open questions in `docs/PROJECT_INTENT.md`.
- Put durable technical decisions in `docs/adr/`.
- Update domain documentation in the same pull request as the behavior or interface it describes.
